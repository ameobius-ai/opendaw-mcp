# v1.6.2 — Studio Settings (2026-07-03)

## What was added

2 new MCP tools: `get_studio_settings()`, `set_studio_setting(category, key, value)`

## StudioPreferences architecture

- `StudioPreferences` from `@opendaw/studio-core` — singleton via `Preferences.host("preferences", StudioSettingsSchema)`
- Uses localStorage key `"preferences"`, zod schema for validation/defaults
- `PreferencesHost` wraps a `VirtualObject<SETTINGS>` — proxy with reactive updates
- `.settings` getter returns the proxy (read/write directly)
- `.subscribe(observer, ...path)` / `.catchupAndSubscribe()` for reactive listening
- `.update(data)` for bulk replacement

## MCP tool implementation notes

### set_studio_setting value type coercion
The tool accepts `value` as `str`. It reads the existing field type from the proxy and coerces:
- `typeof oldVal === 'boolean'` → `newVal = (value === 'true' || value === true)`
- `typeof oldVal === 'number'` → `newVal = parseFloat(value)`
- else → string directly

This handles the schema types automatically without exposing type info to the MCP client.

### Sanitization
`category` and `key` are sanitized via `safe_` pattern (replace quotes/backslash/semicolon). `value` uses `json.dumps()` for JS interpolation.

### Reactive consumers (from upstream grep)
- `BufferUnderrunDetector`: reads `engine["stop-playback-when-overloading"]`
- `RegionOverlapResolver`: reads `editing["overlapping-regions-behaviour"]`
- `ClipboardManager`: reads `editing["show-clipboard-menu"]`
- `Project`: reads `engine["auto-create-output-maximizer"]`, `storage["auto-delete-orphaned-samples"]`, `engine["stop-playback-when-overloading"]`
- `StudioService`: reads `visibility["auto-open-clips"]`
