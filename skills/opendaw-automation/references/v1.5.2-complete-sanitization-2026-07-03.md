## Additional fixes in v1.5.2

- **quantize_notes division parser**: `float("1/4")` was crashing with ValueError. Now parses fraction notation: `if '/' in division: num, den = division.split('/'); grid_ticks = int(float(num.strip()) / float(den.strip()) * 960)`. Results: "1/4"→240, "1/8"→120, "1/16"→60, "1/32"→30.
- **Dead stub removed**: `_find_script_device_js` (pass-only, unused function from early scriptable device development)
- **Scriptable device error messages**: 5 `"{device_type}"` interpolations in error strings replaced with `" + dt + "` JS string concat (uses already-sanitized `dt` variable)
- **create_send src_unit**: str→int type fix (was numeric index with wrong type)
- **set_region_position position_beats**: int→float type fix

## Intentional raw interpolations (by design, NOT sanitized)

1. `evaluate_raw(script)` — raw JS execution, core function purpose
2. `wait_for_condition(condition_js)` — raw JS expression for Boolean() evaluation
3. `add_automation(points)` — JS array literal format `[[pos, val], ...]`

These accept raw JS by design — sanitizing them would break functionality.

## Mass-sanitization script approach

When sanitizing 10+ functions, use a Python script to batch-insert `safe_` definitions:

```python
# For each (func_name, param, safe_var):
# 1. Find function start/end
# 2. Insert safe_var definition before `result = await bridge.evaluate`
# 3. Replace `"{param}"` with `"{safe_var}"` in function body
# 4. Fix indentation: lines starting with `result = await` that lost their 4-space indent
```

**Indentation fix pattern** (run after batch insertion):
```python
lines = source.split('\n')
for i, line in enumerate(lines):
    if line.startswith('result = await bridge.evaluate'):
        if i > 0 and lines[i-1].strip().startswith('safe_') and lines[i-1].startswith('    '):
            lines[i] = '    ' + line
```

This fixed 19 broken lines in one pass during v1.5.2 development.

## Audit methodology

1. AST parse to find all `str`-typed params in `mcp_opendaw_*` functions
2. For each str param, search for `"{param}"` pattern in function body (JS string literal interpolation)
3. Cross-reference: if `safe_param` or `json.dumps(param)` exists in body → sanitized
4. If neither → unsanitized, needs fix
5. Whitelist: params validated before use (e.g. `module_type` checked against `type_map` dict), raw JS by design (script, condition_js, points)
