## Context

After v1.7.0 (DawProject interop), the "API surface exhaustion" conclusion (pattern #76) was revisited. The Engine interface (`packages/studio/core/src/Engine.ts`) was found to expose runtime methods beyond transport that were not covered by MCP tools. This shifted the research pattern from "adapter audit" to "core module audit" — looking at Engine, StudioPreferences, DawProject namespaces instead of adapter getters.

## Engine Interface (Engine.ts)

```typescript
interface Engine extends Terminable {
    play(): void
    stop(): void
    setPosition(position: ppqn): void
    panic(): void              // ← NEW: stop all notes
    sleep(): void
    wake(): void
    scheduleClipPlay(clipIds: ReadonlyArray<UUID.Bytes>): void   // ← NEW
    scheduleClipStop(trackIds: ReadonlyArray<UUID.Bytes>): void  // ← NEW
    
    get position(): ObservableValue<ppqn>
    get bpm(): ObservableValue<bpm>
    get isPlaying(): ObservableValue<boolean>
    get isRecording(): ObservableValue<boolean>
    get isCountingIn(): ObservableValue<boolean>
    get cpuLoad(): ObservableValue<number>      // ← NEW: 0..1
    get markerState(): ObservableValue<Nullable<[UUID.Bytes, int]>>  // ← NEW
}
```

`EngineFacade` implements all as `DefaultObservableValue` wrappers synced from the worklet via `catchupAndSubscribe`.

## Tools Added

### engine_panic()
- Calls `h.engine.panic()` — sync, no `editing.modify()` needed
- Stops all hanging notes immediately (MIDI panic button)
- E2E: returns `{success: true, action: "panic"}` ✅

### get_engine_status()
- Reads all ObservableValue getters in one call
- Returns: `is_playing`, `position_beats` (ppqn / h.ppqn.Quarter), `bpm`, `cpu_load` (0..1), `is_recording`, `is_counting_in`, `marker` ([uuid, index] or null), `engine_started` (via `DAW_engineStarted()`)
- E2E: returns `{is_playing: false, position_beats: 0, bpm: 12, cpu_load: 0, is_recording: false, is_counting_in: false, marker: null, engine_started: false}` before engine start ✅
- Note: bpm=12 is the EngineFacade default before worklet connects; actual project BPM comes from timelineBox

### schedule_clip_play(clip_ids)
- Accepts comma-separated clip UUID strings
- Resolves UUIDs against `rootBox.clips.pointerHub.incoming()` boxes
- Calls `h.engine.scheduleClipPlay(targetUuids)` with openDAW UUID objects
- Returns `{success: true, triggered: N}` or `{error: "No matching clips found"}`

### schedule_clip_stop(track_ids)
- Accepts comma-separated track UUID strings
- Resolves UUIDs against `h.allAUs()` → `au.tracks.collection.adapters()` → `track.uuid`
- Calls `h.engine.scheduleClipStop(targetUuids)` with UUID objects
- Returns `{success: true, stopped: N}` or `{error: "No matching tracks found"}`

## Pre-existing Bug Found (NOT fixed)

### transport(action) ignores action parameter
`mcp_opendaw_transport(action: str)` accepts "play"/"stop"/"toggle" but the JS body:
```js
if (eng.isPlaying?.getValue?.()) {
    eng.stop();
} else {
    eng.play();
}
```
Always toggles regardless of `action` arg. Passing `action="play"` when already playing will STOP. This is noted as pattern #78 but not fixed — `get_engine_status()` now provides the state info to work around it.

## E2E Test Pattern

```python
from server import bridge, mcp_opendaw_engine_panic, mcp_opendaw_get_engine_status

async def test():
    await bridge.start()
    r = await mcp_opendaw_get_engine_status()
    # → {is_playing: false, bpm: 12, cpu_load: 0, engine_started: false, ...}
    r2 = await mcp_opendaw_engine_panic()
    # → {success: true, action: "panic"}
    await bridge.stop()
```

No Vite/engine start needed — tools work on the EngineFacade defaults. `panic()` works even without engine started (no-op on empty engine).

## Key Insight

When adapter getters are saturated (pattern #76), shift to **core module audit**: read `Engine.ts`, `StudioPreferences.ts`, `DawProject.ts` — these are singleton/namespaces with methods that don't show up in adapter class scans. The engine interface alone yielded 4 tools (panic, status, clip scheduling). Future candidates: `engine.sleep()`/`wake()`, `engine.noteSignal()` (live MIDI input), `engine.subscribeNotes()` (note event stream).
