## v1.7.3 — Instrument Automation (tools #225-226)

### add_instrument_automation
```python
async def mcp_opendaw_add_instrument_automation(unit_index: int, parameter_name: str, points: str, sample_index: int = -1) -> str:
```
- Automates any instrument field that supports `Pointers.Automation`
- `sample_index >= 0` → targets specific Playfield sample box (for mute/volume/pan per drum)
- `sample_index = -1` → targets top-level instrument field (Vaporisateur cutoff, Tape flutter)
- Uses `api.createAutomationTrack(au, field)` — same API as effect automation but on instrument box
- Sanitization: `safe_param = parameter_name.replace('"','').replace('\\','').replace("'","")`
- `points` is raw JS array (by design): `[[0, 0.5], [4, 1.0]]`

### list_automatable_fields
```python
async def mcp_opendaw_list_automatable_fields(unit_index: int, sample_index: int = -1) -> str:
```
- Returns all fields with `automatable: true/false`
- Uses `Pointers.Automation = 9` to check: `field.pointerRules.accepts.includes(9)`

### Key discovery: Pointers.Automation detection
- `window.DAW_Pointers` already in headless-daw globals (line 355 of main.ts)
- `Pointers.Automation` = numeric enum value `9`
- `field.pointerRules.accepts` = array of numeric Pointer values (e.g. `[27, 9, 22]`)
- Check: `accepts.includes(9)` → automatable
- `NoPointers` fields (like `enabled` on EffectBox) have `pointerRules.accepts` that does NOT include 9

### Key discovery: record() returns numeric keys
`box.record()` returns `{"1": field, "2": field, ...}` — NOT `{"volume": field, ...}`.
Must use `field._fieldName` to get the actual field name when iterating.

### E2E test
1. Create Vaporisateur → unit_index=1
2. `list_automatable_fields(1)` → 18/23 automatable (volume, cutoff, resonance, attack, decay, release, filterEnvelope, octave, tune, waveform, ...)
3. `add_instrument_automation(1, "cutoff", "[[0,200],[4,8000],[8,200]]")` → 3 events created ✅

### Upstream issue coverage
- #269 (playfield mute automation) → `mute` field on PlayfieldSampleBox supports `Pointers.Automation` → **COVERED** via `add_instrument_automation` with `sample_index`
- #270 (automate effect enable/disable) → `enabled` field has `pointerRules: NoPointers` → **BLOCKED** on upstream architecture, cannot fix via MCP

## v1.7.4 — Engine Sleep/Wake + Loading Check (tools #227-229)

### engine_sleep / engine_wake
```python
async def mcp_opendaw_engine_sleep() -> str:  # h.engine.sleep()
async def mcp_opendaw_engine_wake() -> str:   # h.engine.wake()
```
- Suspends/resumes audio processing to save CPU
- Useful when doing non-audio operations (box editing, project manipulation)

### query_loading_complete
```python
async def mcp_opendaw_query_loading_complete() -> str:
```
- `eng.queryLoadingComplete()` returns Promise<boolean> — all samples loaded?
- `eng.isReady` — engine initialized?
- Must use `async () =>` in evaluate since it awaits

### get_effect_chain improvement
Before: `type: box.constructor.name` → "DelayDeviceBox"
After:
```javascript
const className = box.constructor.name;
const shortName = className.replace(/DeviceBox$/, "").replace(/Box$/, "");
return { type: shortName, class: className, enabled: ..., minimized: ..., label: ... };
```
Applied to both `get_effect_chain` and `get_midi_effect_chain` (replace_all=true).

### E2E test
- sleep ✅, wake ✅, loading (loaded=false, is_ready=true) ✅
- Effect chain: type=Delay, class=DelayDeviceBox, enabled=true, minimized=false ✅
