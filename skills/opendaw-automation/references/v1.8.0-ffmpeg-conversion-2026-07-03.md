## Technique: System ffmpeg vs Browser WASM

openDAW's upstream uses `FFmpegWorker` (`packages/studio/core/src/ffmpeg/FFmpegWorker.ts`) which downloads ~30MB WASM from `package.opendaw.studio` CDN at runtime. In headless mode through VPN, this is fragile and slow.

**Solution**: Use system ffmpeg (`/usr/bin/ffmpeg`, v4.4.2+) via `asyncio.create_subprocess_exec`. More reliable, no download needed, works in any headless environment.

### convert_audio implementation pattern
```python
@mcp.tool()
async def mcp_opendaw_convert_audio(filename: str, format: str = "mp3", bitrate: str = "320k", quality: int = -1) -> str:
    import shutil as _shutil
    if not _shutil.which("ffmpeg"):
        return _wrap_eval({"error": "System ffmpeg not found"})
    # Build command
    cmd = ["ffmpeg", "-y", "-i", wav_path]
    if fmt == "mp3":
        if quality >= 0: cmd += ["-q:a", str(quality)]  # VBR
        else: cmd += ["-b:a", bitrate]                   # CBR
    elif fmt == "flac":
        cmd += ["-compression_level", "8"]
    cmd.append(out_path)
    # Run asynchronously
    proc = await asyncio.create_subprocess_exec(
        *cmd, stdout=asyncio.subprocess.PIPE, stderr=asyncio.subprocess.PIPE
    )
    await proc.communicate()
    if proc.returncode != 0:
        return _wrap_eval({"error": f"ffmpeg exited with code {proc.returncode}"})
```

**Key**: `await proc.communicate()` not `proc.wait()` — communicate() reads stdout/stderr pipes and prevents deadlocks. `proc.wait()` alone can deadlock if pipe buffers fill.

### E2E results
- WAV 1.01MB → MP3 0.11MB (ratio 0.106, 320k CBR)
- WAV 1.01MB → FLAC 0.19MB (ratio 0.194, compression_level 8)

## Technique: _unwrap_eval for Chaining MCP Tools

When one MCP tool calls another (e.g. `render_full_format` calls `render_full` then `convert_audio`), the result is a JSON string from `_wrap_eval`. Need to parse it back:

```python
def _unwrap_eval(s) -> any:
    """Parse a JSON string from _wrap_eval back to dict/list."""
    if isinstance(s, str):
        try: return json.loads(s)
        except: return s
    return s
```

Usage in `render_full_format`:
```python
wav_result = await mcp_opendaw_render_full(filename, sample_rate)
# Check for error in the JSON string
if "error" in str(wav_result).lower() and "success" not in str(wav_result).lower():
    return wav_result
conv_result = await mcp_opendaw_convert_audio(filename, fmt, bitrate, -1)
return _wrap_eval({
    "render": _unwrap_eval(wav_result),
    "conversion": _unwrap_eval(conv_result),
})
```

**Pitfall**: `mcp.call_tool()` returns a tuple `(content_list, structured_data)` when called programmatically, not a string. The content_list contains `TextContent` objects with `.text` attribute. For internal calls between tools, call the function directly (`await mcp_opendaw_render_full(...)`) not via `mcp.call_tool()`.

## Bugfix: AudioData.numberOfChannels (NOT channels)

`capture_realtime` returned `channels: audioData.channels` — but `AudioData` type has no `channels` property:

```typescript
// AudioData type (packages/lib/dsp/src/audio-data.ts)
export type AudioData = {
    sampleRate: number
    numberOfFrames: number
    numberOfChannels: number  // NOT "channels"!
    frames: ReadonlyArray<Float32Array>
}
```

`audioData.channels` → `undefined` → `JSON.stringify(undefined)` omits the key entirely. Fixed to `audioData.numberOfChannels`.

**Lesson**: Always cross-reference TypeScript type definitions when accessing properties returned from JS evaluate. The `AudioData` type is small and well-defined — always use `numberOfChannels`, `numberOfFrames`, `sampleRate`, `frames`.

## TrackBox Fields (verified July 3)

TrackBox has NO name field. Track display names come from AudioUnitBox, not TrackBox.

```typescript
// TrackBoxFields — all fields:
1: tracks (PointerField<TrackCollection>)
2: target (PointerField<Automation>)
3: regions (Field<RegionCollection>)
4: clips (Field<ClipCollection>)
10: index (Int32Field)
11: type (Int32Field) — 0=Undefined, 1=Notes, 2=Audio, 3=Value
20: enabled (BooleanField, default true)
30: excludePianoMode (BooleanField, default false)
```

Upstream issue #212 (automation track naming) — TrackBox has no name to set. `add_automation` passes `{name: paramName}` to `createValueClip`, which sets the clip label, not the track name. This is the best we can do without upstream changes.

## Upstream FFmpeg Architecture (for reference)

```
FFmpegWorker (FFmpegWorker.ts)
  ├── static async load() → downloads WASM from CDN
  ├── mp3Converter() → Mp3Converter (mp3.ts)
  └── flacConverter() → FlacConverter (flac.ts)

Mixdowns.ts (UI layer)
  ├── saveMp3File → ffmpeg.mp3Converter().convert(wavBlob, progress, {bitrate/quality})
  ├── saveFlacFile → ffmpeg.flacConverter().convert(wavBlob, progress, {compression})
  └── saveWavFile → WavFile.encodeFloats(audioData) directly

Mp3Converter: -i input.wav -b:a 320k OR -q:a {0-9} output.mp3
FlacConverter: -i input.wav -compression_level {0-12} output.flac
```

Our MCP tools replicate this command-line interface but use system ffmpeg instead of WASM. Same flags, same quality options.
