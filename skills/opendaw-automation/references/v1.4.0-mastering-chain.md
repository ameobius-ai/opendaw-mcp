## measure_lufs implementation

### Problem
Was `return _err("Not yet reconstructed")` — a stub from the .pyc recovery era.

### Solution: pure Python BS.1770-4
- **Manual WAV parsing**: Python `wave` module raises "unknown format: 3" on 32-bit float WAVs (audio_format=3). Must parse RIFF/WAVE header manually: iterate chunks (`fmt ` for metadata, `data` for audio bytes), then `struct.unpack(f"<{count}f", audio_data)` for float32.
- **K-weighting**: Two biquad stages computed from BS.1770-4 Annex formulas. **CRITICAL**: hardcoded coefficient tables from various sources have inconsistent numerator/denominator ordering. Must compute from `f0`, `G`, `Q` → `K=tan(π*f0/sr)` → biquad coeffs. Function signature: `apply_biquad(data, b0, b1, b2, a0, a1, a2)` — numerator (b) first, normalized by a0.
- **Gated mean squares**: 400ms blocks, 75% overlap (100ms hop), absolute gate -70 LUFS, relative gate -10 LU below mean of absolutely-gated blocks.
- **LUFS = -0.691 + 10*log10(gated_mean_square)**
- No numpy dependency — pure Python `struct` + `math`.

### E2E result
- `lufs_test.wav` (3-note Vaporisateur chord, 32-bit float, 48kHz, stereo)
- LUFS: -16.2, true peak: -5.49 dBTP, 19 blocks measured, 19 gated
- Full production pipeline: -18.3 LUFS pre-master, -3.71 dBTP

## auto_gain implementation

### Problem
Was a single Maximizer threshold set — no iteration, no LUFS measurement, no convergence.

### Solution: iterative render-measure-adjust
1. Ensure Maximizer on output AU (create if missing)
2. For each iteration (max 3):
   - Set Maximizer threshold + output AU volume
   - `OfflineEngineRenderer.start(p.copy(), Option.None, ...)` → render
   - Save WAV via base64 round-trip
   - Call `measure_lufs()` on saved WAV
   - Check convergence (±1 LUFS)
   - Adjust: bidirectional

### Bidirectional adjustment
- **Too quiet** (diff < 0): lower Maximizer threshold → more makeup gain
- **Too loud** (diff > 0): lower output AU `volume` field → attenuation

### CRITICAL: output AU volume field stores dB directly
- `au.volume` on Output AudioUnitBox: unit="dB", min=-96, max=+6
- `getValue()` returns 0 for 0dB, -6 for -6dB — DIRECT dB values
- NOT normalized 0..1 like instrument AU volume (where 0.767835 ≈ 0dB)
- Initial code converted dB→linear→0.768 multiplier → near-zero effect
- Fix: `au.volume.setValue(volume_db)` directly

### E2E convergence
- Target: -14 LUFS
- iter 1: -6.0 LUFS, vol=0dB (too loud by +8)
- iter 2: -12.4 LUFS, vol=-6.4dB (closing in)
- iter 3: -13.7 LUFS, vol=-7.68dB, diff=+0.3 → **converged** ✅

## render_range (was stub → real render)

Was returning only BPM. Now: `OfflineEngineRenderer.start(p.copy(), Option.wrap({range: {start: ppqn, end: ppqn}}), ...)`. ExportConfiguration.range accepts `"full"` or `{start, end}` in ppqn. Beats → ppqn via `Math.round(beat * PPQN.Quarter)`.

## AU sorting fix (systemic, 80+ sites)

`pointerHub.incoming()` returns AUs in arbitrary order (insertion order). `DAW_HELPERS.au(i)` uses `adapters()` which sorts by index — but raw box-level access was unordered. Fix: `.sort((a, b) => (a.index?.getValue?.() ?? 0) - (b.index?.getValue?.() ?? 0))` on all 80+ `pointerHub.incoming()` calls.
