## Critical Fix: MIDI Export Velocity

`export_midi` used `Math.round(note.velocity.getValue() * 127 / 100)` — the `/ 100` is wrong.
openDAW velocity is 0..1 (float), not 0..100.

**Before:** vel=1.0 → MIDI 1, vel=0.787 → MIDI 1 (near-zero for ALL notes)
**After:** vel=1.0 → MIDI 127, vel=0.5 → MIDI 64, vel=0.787 → MIDI 100

E2E verified with 3 notes at different velocities.

## import_midi offset_beats Bug

`offset_beats: str` parameter used as `int(offset_beats * 960)`.
In Python, `"4.0" * 960` = string repetition (960 copies of "4.0"), NOT 3840.
Fix: `int(float(offset_beats) * 960)` → then type annotation fixed to `float` → `int(offset_beats * 960)`.

## Mass-Replace Pitfall

When doing `source.replace(old, new)` for multi-param signatures, the ORDER of params
in the replacement string must match the file EXACTLY. `loop_beats` was missed because:

- Replacement pattern: `loop_beats: str, loop_offset_beats: str, event_offset_beats: str`
- Actual file content: `loop_beats: str, loop_offset_beats: float, event_offset_beats: float`
  (the latter two were already fixed in a prior pass)

**Lesson:** Always run `scripts/audit_str_params.py` after mass replacements — it catches stragglers
that the bulk replace missed due to partial prior fixes.

## Redundant Wrapper Cleanup

After fixing param types from `str` to `float`/`int`, explicit conversion wrappers become redundant:
- `vol_db = float(volume_db)` → `vol_db = volume_db` (volume_db now float)
- `target = float(target_lufs)` → `target = target_lufs` (target_lufs now float)
- `max_iter = int(max_iterations)` → `max_iter = max_iterations` (max_iterations now int)

Harmless but adds noise. Clean up after type fixes.
