# v1.7.0 — DawProject Interop (2026-07-03)

## What was added

2 new MCP tools (217→219 total):
- `export_dawproject(filename)` — export current project as .dawproject ZIP (Bitwig/Ableton/rePitch compatible)
- `import_dawproject(filename)` — import .dawproject ZIP into current session

## API surface

### DawProject namespace (`@opendaw/studio-core`)
- `DawProject.encode(skeleton, sampleManager, metaData)` → `Promise<ArrayBuffer>` — async, uses JSZip
- `DawProject.decode(buffer)` → `Promise<{metaData, project, resources}>` — async, uses JSZip
- Skeleton = `{boxGraph: project.boxGraph, mandatoryBoxes: ProjectSkeleton.findMandatoryBoxes(project.boxGraph)}`
- MetaData = `{application: {name: "openDAW-MCP", version: "1.7.0"}}`

### DawProjectImport namespace (`@opendaw/studio-core`)
- `DawProjectImport.read(schema, resources)` → `Promise<{audioIds, skeleton}>`
- schema = ProjectSchema from decode
- resources = ResourceProvider from decode

### Headless-daw globals added
```typescript
import { DawProject, DawProjectImport } from "@opendaw/studio-core";
w.DAW_DawProject = DawProject;
w.DAW_DawProjectImport = DawProjectImport;
```

## Export tool implementation

1. JS: `DawProject.encode(skeleton, sampleManager, metaData)` → ArrayBuffer
2. JS: ArrayBuffer → base64 via `btoa(String.fromCharCode(...bytes))`
3. Python: `base64.b64decode(b64)` → write to `OPENDAW_EXPORT_DIR/{filename}.dawproject`

## Import tool implementation

1. Python: read file → base64 encode
2. JS: `atob(base64)` → Uint8Array → ArrayBuffer
3. JS: `DawProject.decode(buffer)` → `{metaData, project, resources}`
4. JS: `DawProjectImport.read(project, resources)` → `{audioIds, skeleton}`
5. JS: `DAW_loadProject(ProjectSkeleton.encode(result.skeleton.boxGraph))` → new project

## Pitfalls

1. **`DawProjectImport` not `DawProjectImporter`** — the file is `DawProjectImporter.ts` but the exported namespace is `DawProjectImport`. Import as `DawProjectImport` from `@opendaw/studio-core`.

2. **JSZip is in headless-daw/node_modules, NOT openDAW** — `jszip` is not listed in any openDAW package.json. It's installed in headless-daw's node_modules. `ExternalLib.JSZip()` does dynamic `import("jszip")` with retry (up to 10 attempts). Vite resolves it through headless-daw's dependency tree.

3. **`DawProject.encode` is async** — must `await` inside `async () => {}` evaluate block. The JSZip dynamic import is async.

4. **Skeleton construction** — `ProjectSkeleton.findMandatoryBoxes(project.boxGraph)` walks the box graph to find rootBox, primaryAudioBusBox, primaryAudioUnitBox, timelineBox, userInterfaceBoxes. This is the same function used by `ProjectSkeleton.decode()`.

5. **Base64 round-trip for large files** — same pattern as WAV export (#46). For large projects with many samples, the base64 string can be very large. The bridge evaluate channel handles it but may be slow for >100MB projects.

6. **MetaData schema** — `MetaDataSchema` from `@opendaw/lib-dawproject`. Minimal valid: `{application: {name: "...", version: "..."}}`. Can also include `projectId`, `modified`, `created` fields.
